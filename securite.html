Transparence

Vos fonds ne sont pas chez nous.
Ils sont dans le contrat.

Le marché de crédit n'a pas de caisse administrable. Les jetons sont détenus par le contrat, et les règles sont écrites dedans. Voici exactement ce qui protège les utilisateurs — et ce que l'administrateur peut ou ne peut pas faire.

Les cinq protections réelles

ProtectionComment elle fonctionne
Aucun retrait adminLe contrat n'a aucune fonction permettant à l'administrateur de retirer les jetons. Les seuls transferts sortants vont à l'emprunteur, au liquidateur et à l'agent qui retire sa garantie. ✅ vérifié dans le code
Garantie 150 %Un agent ne peut emprunter que 150 % de sa garantie (jusqu'à 300 % après des remboursements réussis). La garantie est déposée avant tout transfert. ✅
Bornes immuablesTaux maximum, durée maximum (365 jours), nombre de prêts par agent (3), ratio de garantie : ce sont des constant dans le code. L'admin ne peut pas les dépasser. ✅
Remboursement toujours ouvertMême si le marché est en pause, rembourser() fonctionne : personne ne peut être bloqué dans sa dette. ✅
Tout est publicCode, adresses, soldes, transactions : vérifiables sur BscScan par n'importe qui, sans notre permission. ✅

Ce que l'administrateur peut faire — et ne peut pas faire

PeutNe peut pas
  • ajuster le taux, dans la borne maximum
  • ajuster le ratio de garantie, entre 100 % et 300 %
  • fixer la garantie minimale et les capitaux min/max
  • ouvrir ou fermer les inscriptions
  • mettre le marché en pause
  • bloquer un agent précis
  • proposer un changement d'admin (en 2 étapes)
  • retirer les jetons du marché
  • modifier les bornes immuables
  • empêcher un remboursement
  • saisir une garantie sans échéance dépassée
  • changer l'adresse d'un transfert
  • changer l'admin seul

Ce que nous corrigeons avant l'ouverture

  • Bug de remboursement trouvé en test (calcul de la dette) → corrigé dans la version 2, déjà compilée. Aucun utilisateur n'a été exposé : le défaut a été découvert pendant la phase pilote.
  • Recommandation en cours : ajouter un coffre à deux signatures pour l'administration, et un délai de sécurité avant tout changement de paramètre.
  • Aucune souscription publique : l'accès se fait sur dossier, avec vérification d'identité et document de risques signé.

Sécurité du site

  • Pages statiques, hébergées sur GitHub Pages, en HTTPS.
  • Aucun formulaire, aucune base de données, aucun cookie de suivi.
  • Aucune donnée personnelle collectée par ce site : le contact se fait par e-mail.
  • Les paiements sont traités par PayPal ; aucune carte ne transite par ce site.
  • Aucune clé privée, aucun secret, aucune clé d'API dans le code des pages.
